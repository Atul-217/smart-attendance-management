4. Core Attendance Features

Implement the following features:

A. Attendance Check-in

- Students can attempt to mark attendance.
- Record student ID, date, time, subject, status and verification method.
- Prevent duplicate attendance for the same student, subject and session.
- Display a clear success or rejection message.
- Allow the admin to view the attendance record immediately.

B. Location Verification

- Use the browser Geolocation API only after the student grants permission.
- For a demo, allow the admin to configure a sample college location and permitted radius.
- Show whether the student is within the permitted area when actual coordinates are available.
- Handle permission denial and unavailable location gracefully.
- Do not pretend that a simulated location is a verified real location.

C. QR Code Attendance

- Generate a QR code for a specific class or attendance session.
- Allow students to scan a QR code using the device camera when supported, or enter a session code as a fallback.
- Validate the session code and expiry time.
- Prevent repeated check-ins for the same session.
- Clearly distinguish simulated verification from real QR scanning.

D. Face Recognition

- Provide a face-verification interface for demonstration.
- For the demonstration, camera preview may be used only after explicit user action and permission; do not identify people or save images.
- If actual face verification is implemented, use a suitable browser-compatible solution with explicit camera permission and consent.
- Do not mark a student present merely because the camera opens or a face is detected.
- Clearly label simulated face verification as a demo.
- Never claim that the demo can reliably identify a person's identity without a genuine identity-verification implementation.

E. Attendance Records

- Show daily, weekly and monthly attendance.
- Display subject-wise attendance percentages.
- Include Present, Absent, Late and Rejected Attempt statuses.
- Allow filtering by student, date, subject and status.
- Show attendance statistics using simple charts or progress bars.

F. Proxy Attendance Prevention

- Detect duplicate check-in attempts.
- Validate QR/session expiry.
- Combine available location and session verification results.
- Flag suspicious attempts for admin review.
- If proxy attendance is confirmed by the configured verification rules, reject the check-in and mark the student absent for that session.
- Record the reason for rejection.
- Do not automatically accuse a student based only on a single failed location or camera check.
- Clearly explain that a frontend-only demo cannot guarantee prevention of all proxy attendance.
